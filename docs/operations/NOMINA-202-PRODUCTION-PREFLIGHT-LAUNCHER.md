# Nómina 202: lanzador de preflight READ ONLY

El lanzador `src/scripts/nomina-turno-202-production-launcher-cli.ts` solo llama al runner PostgreSQL READ ONLY. No importa el corrector ni acepta estados ACTIVE. Requiere los 14 argumentos `--nombre=valor` en el orden estricto exportado por `ARGUMENT_ORDER`. El destino ya no se aporta desde la CLI: se fija en `src/scripts/nomina-202-production-target-pin.json`, un artefacto versionado sin usuario, contraseña, URL completa, token ni project ref en claro. El precheck valida su SHA-256 y vuelve a leer las evidencias versionadas para comprobar host, puerto, base y hash del project ref. No existe búsqueda automática de `.env`.

Las rutas del lanzador se aceptan con separadores Windows `/` o `\`, se normalizan con `path.win32` y desde ese momento se comparan en forma canónica. Se rechazan rutas relativas, drive-relative, UNC/device, ADS, componentes `.`/`..`, reparse points y cualquier diferencia entre la ruta final real y la autorizada. La lectura de `.env` usa únicamente la ruta absoluta dada por `--env-file`, tras revisar archivo regular, ACL y estabilidad de identidad/tamaño/mtime. Solo extrae las cuatro variables enumeradas; no llama a `dotenv.config`, no modifica `process.env`, rechaza duplicados de variables requeridas y limpia el objeto mutable al finalizar. Ningún valor o referencia documental se incluye en logs o recibos. Los errores del CLI se reducen a códigos estables.

Procedencia de destino: host fijado por `reports/nomina-operacion-real-audit-2026-08-31.json` y corroborado por `reports/territorial-contract-24-pre-migration.json`; puerto y base por el segundo reporte; hash del project ref calculado en memoria desde el hostname de Supabase del primer reporte; política TLS por el blob del runner certificado en `6ea616b5442c0654e2f3cc88ddf28dea381c4370` (SHA-256 `3841b8060b423b37e3d0ea645e700e59d8932829b37c6e04f383cf9533646738`). El artefacto `nomina-202-production-target-pin.json` fija las rutas, commits y SHA-256 de esas fuentes. El validador vuelve a comprobar las fuentes antes de leer credenciales y nunca imprime ni almacena el project ref en claro. La configuración leída de `DATABASE_URL` y `SUPABASE_URL` se compara con esos cuatro pins; host alternativo, puerto alternativo, base distinta, ref distinto o TLS no verificado producen STOPPED.

Los dos recibos se publican con creación exclusiva y enlaces duros atómicos en rutas `baseline` y `pending` distintas. El recibo pendiente enlaza ruta relativa y SHA del baseline. No hay ruta `committed` expuesta al lanzador.

La certificación de este lanzador debe ejecutarse solamente con variables, CA, PostgreSQL TLS y Storage sintéticos. La evidencia de pruebas no habilita conexiones productivas ni activa el nonce.
